1. 保留现有学习记录与安装升级依赖的标识和数据路径：IndexedDB `kotoba-v1`、Windows Origin `kotoba://app`、Cloudflare Pages 项目 `kotoba`、R2 `kotoba-assets`。当前 Windows 包已使用 `kotobud-desktop` 与 `app.kotobud.desktop`，本轮只调整版本号；不要根据旧交接中的 `kotoba-desktop` / `org.kotoba.desktop` 再次改名，存量升级行为仍须人工验收。
2. 学习记录跨端同步使用 Cloudflare D1；CloudBase 用于身份相关能力，不建第二套业务库。小程序须完成有效 Pull、校验、确定性对齐和本地持久化后才允许 Push；失败或账号切换时禁止空快照覆盖云端。
3. Web 更新先构建**当前工作树**，再用 `node scripts/deploy_pages.cjs staging` 部署测试分支并在测试域名验收；命令中的 `staging` 是 Pages 部署分支参数，不能代替检查本地 Git 分支和未提交内容。生产在微信环境与迁移就绪前须保持 Web-only Worker：生产构建后执行 `node scripts/prepare-web-only-production-worker.cjs`，再由 `deploy_pages.cjs main` 的哈希门禁核对。Preview D1 与生产 D1 分开，R2 `kotoba-assets` 仍共享，避免覆写共用对象 key。
4. Windows 下载入口只在 R2 对象列表、精确大小、校验文件、公网 `HEAD`/Range `GET` 和页面链接均复核后开放。构建前显式设置 `VITE_WINDOWS_DOWNLOADS_READY`，避免 Web 应用与静态下载页对未设置值采用不同默认状态；未验证的新包使用 `false`。打包与上传可交给子代理；主代理负责复核与发布判断。
